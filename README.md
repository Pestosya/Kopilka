# Копилка

Обновлённое приложение для личных финансов на основе исходного прототипа.

## Что внутри

- доходы и расходы с поиском и фильтрами;
- отдельные наличные, банковские карты и накопительные счета;
- переводы между своими счетами без искажения статистики доходов и расходов;
- регулярные зарплаты, подписки и коммунальные платежи с автоматическим созданием операций;
- напоминания заранее внутри приложения и системные уведомления по разрешению пользователя;
- кредиты, микрозаймы и личные долги с количеством платежей и датами;
- расчёт процентов, тела кредита, следующего платежа и остатка графика;
- аннуитетные и дифференцированные кредиты, комиссии, пени и банковское округление;
- досрочное погашение с уменьшением срока или размера платежа;
- календарь будущих платежей с разбивкой по дням и месяцам;
- финансовый пульс и подсказки;
- прогноз баланса, динамика капитала и сравнение месяцев;
- стратегии погашения долгов «снежный ком» и «лавина»;
- цель финансовой подушки;
- светлая и тёмная темы;
- резервные копии и импорт данных из старого прототипа;
- установка на компьютер или телефон и работа офлайн.
- простая регистрация локального личного кабинета только по логину и паролю;
- несколько отдельных локальных аккаунтов с быстрым переключением;
- единое меню профиля с фотографией, настройками, темой и выходом;
- блокировка приложения паролем или PIN-кодом и поддержка системной биометрии;
- пароль для расшифровки базы после полного перезапуска; PIN и биометрия — для повторной блокировки в текущем сеансе;
- усиленное хеширование паролей PBKDF2, защита от перебора и автоматическое обновление старых хешей;
- настраиваемая автоблокировка и блокировка после сворачивания приложения;
- шифрование локальной финансовой базы AES-256 отдельным случайным ключом;
- зашифрованные резервные копии AES-256 с отдельным паролем;
- одинаковый набор основных функций на компьютере и телефоне.

## Запуск

Откройте папку в локальном веб-сервере и перейдите на `index.html`. Например:

```bash
python3 -m http.server 4173
```

После этого откройте `http://localhost:4173`. В разделе «Настройки» браузер предложит установить приложение, если поддерживает PWA.

Все финансовые данные хранятся локально в браузере. Для надёжности периодически скачивайте резервную копию в разделе «Настройки».

## Публикация на GitHub Pages

Фронтенд — статический, поэтому раздаётся бесплатно через GitHub Pages (CDN, выдерживает большое число пользователей).

1. Закоммитьте и запушьте проект в ветку `main`.
2. В репозитории: **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` прогоняет тесты и публикует сайт при каждом пуше.

Приложение откроется на `https://<пользователь>.github.io/<репозиторий>/`.

## Облачная синхронизация (Supabase)

Синхронизация между устройствами — сквозное шифрование (E2E): сервер хранит только зашифрованный файл, открытых финансов не видит.

Как устроено:

- из пароля синхронизации выводятся два независимых ключа — `authKey` (вход в Supabase) и ключ шифрования базы; зная `authKey`, сервер не может расшифровать данные;
- на сервер уходит только `kopilka-encrypted-profile` (AES‑GCM‑256) и обёрнутый паролем ключ базы;
- версия хранилища на сервере разрешает конфликты при правках с двух устройств.

Подключение бэкенда:

1. Создайте бесплатный проект на [supabase.com](https://supabase.com).
2. Выполните `supabase/schema.sql` в **SQL Editor** (таблица `vaults`, RLS, функция `push_vault`).
3. В `sync-config.js` укажите **Project URL** и **publishable‑ключ** (Settings → API). Публиковать secret‑ключ нельзя.
4. Откройте приложение → **Настройки → Синхронизация** → создайте аккаунт или войдите.

Ограничение первой версии: разрешение конфликтов работает по принципу «последняя запись побеждает». Если два устройства правили данные офлайн одновременно, при синхронизации победит более новая версия. Синхронизируйтесь до и после изменений; полноценное слияние — в планах.

## Структура и проверка

- `modules/migrations.js` — версии формата данных и безопасное обновление старых сохранений;
- `modules/finance.js` — независимые финансовые расчёты;
- `modules/security.js` — хеширование, шифрование, расшифровка и вывод ключа авторизации;
- `modules/sync.js` — клиент серверной синхронизации (Supabase Auth + REST через `fetch`, без SDK);
- `sync-config.js` — публичные настройки синхронизации (URL и publishable‑ключ);
- `supabase/schema.sql` — серверная схема: таблица зашифрованных хранилищ, RLS и разрешение конфликтов;
- `app.js` — интерфейс и связывание модулей.

Тесты гоняются в CI (GitHub Actions) перед деплоем и локально при установленном Node:

```bash
npm test
```
